# BOQ attachment audit

อัปเดตล่าสุด: 3 กันยายน 2569

หมายเหตุสถานะ: ตารางและตัวเลขตัวอย่างด้านล่างเป็นหลักฐานการตรวจ ณ 3 กันยายน 2569 จึงคงไว้เพื่อ traceability การนับ current ที่ยืนยันซ้ำเมื่อ 21 กันยายน 2569 คือ 13 หมวด / 123 รายการตรวจ / 170 ช่องหลักฐาน และ 42 cleaning evidence slots ตามชุดตรวจปัจจุบัน ดู [Document Status](document-status.md) และ `node tools/run_all_tests.mjs` สำหรับสถานะล่าสุด

เอกสารชุดนี้แยกข้อมูลออกจากกันอย่างชัดเจน:

- `เอกสารประกอบ`: ตรวจว่ารายการในลิสมีไฟล์ประกอบครบหรือไม่
- `หลักฐานประกอบการตรวจ`: ตรวจว่าช่องภาพ/หมายเหตุในไฟล์มีหลักฐานครบถ้วนหรือไม่

## ผลตรวจ

เอกสารประกอบครบถ้วน `13/13` รายการ แต่หลักฐานภายในเอกสารยังไม่ครบถ้วนทุกช่อง รายการที่มีสถานะ `หลักฐานไม่ครบถ้วน`, `ไม่ได้ติดตั้ง`, `ไม่มีภาพถ่าย` หรือ `จัดเก็บไว้ที่เครื่องแม่ข่ายประจำสถานี` ยังคงเป็นข้อมูลสถานะจากเอกสารต้นทาง ไม่ได้ถูกตีความว่าเป็นคำสั่งใหม่

ระบบใช้รายการหลักฐานกลางรุ่น `checklist-master-v5-system-mapped` เป็นแม่แบบปัจจุบันสำหรับรอบใหม่ และรองรับ `checklist-master-v3-boq-evidence`/`checklist-master-v4-asset-mapped` เพื่ออ่านข้อมูลประจำรอบเดิม โดยแยกสถานะที่พบใน PDF เป็น `sourceObservedStatus` และเริ่มรอบใหม่ด้วย `ยังไม่ได้ระบุ` ทุกช่อง สำหรับรอบใหม่มีนโยบาย `equipment-cleaning-v1` เพิ่มเติม: ตัดช่องทำความสะอาดแบบรวม/ซ้ำและพื้นที่ที่ไม่ใช่เป้าหมายอุปกรณ์ออก แล้วสร้างรายการต่ออุปกรณ์จริงที่ active ในกลุ่ม Computer, ตู้ควบคุม, LPR, Fixed/PTZ, NVR และ Database Server โดยมีภาพบังคับ 3 ช่วง ก่อน/ระหว่าง/หลัง อย่างละ 1 ภาพ

การนับในระบบแยกเป็น 3 หน่วย: ข้อมูลประจำสถานีนับอุปกรณ์จริง, การตั้งค่ารายการตรวจประจำสถานีนับแม่แบบปัจจุบัน 13 หมวด/44 รายการ และรายการหลักฐานกลางนับตาม PDF 13 หมวด/123 รายการตรวจ/170 ช่องหลักฐาน ส่วนข้อมูลประจำรอบตัวอย่างในรายงานฉบับนี้มี 11 อุปกรณ์จริงเป้าหมาย, 33 ช่องภาพทำความสะอาด และ 142 ช่องหลักฐานรวมตาม snapshot ณ วันที่ตรวจ; ตัวอย่างดังกล่าวไม่ใช่ค่าตายตัวของทุกสถานี รอบใหม่สร้างตามทะเบียนอุปกรณ์จริงและนโยบายปัจจุบัน ส่วนข้อมูลประจำรอบ/ฉบับร่างเดิมจะยึดรายการหลักฐานที่เก็บอยู่ในข้อมูลประจำรอบ ช่องที่เป็นอุปกรณ์จริงแต่ไม่มีอุปกรณ์ active ในข้อมูลประจำรอบจะมีสถานะ `ไม่เกี่ยวข้อง` และถูกตัดออกจากความคืบหน้า/ยอดหลักฐานที่ต้องกรอก ส่วน `3.1` ของข้อมูลประจำรอบรุ่นใหม่ใช้ Lane topology และไม่สร้างรายการเมื่อสถานีไม่มี Lane
