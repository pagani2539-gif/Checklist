# Checklist MVP glossary

| คำ | ความหมายใน MVP |
| --- | --- |
| BOQ | หมวดรายการงาน/อุปกรณ์ตามสารบัญในแบบฟอร์มอ้างอิง |
| Mapping 3 ชั้น | `Present MA` ใช้ระบุระบบและจำนวนงาน, `Checklist` ใช้ระบุจุดตรวจ/หลักฐาน, และอุปกรณ์จริงใช้ระบุอุปกรณ์ที่มีตำแหน่งหรือ Serial Number |
| systemId | รหัสระบบภายในที่คงที่ เช่น `wim`, `lpr`, `cctv`, `other`; ไม่ใช้เลขหมวดจากเอกสารเป็นรหัสกลาง |
| stationSystems | รายการระบบจาก Present MA ที่เก็บ `systemId`, ชื่อแสดงผล, `sourceLabel`, จำนวน และเลขอ้างอิงเอกสารใน Station Profile/Snapshot |
| Lane topology | โครงสร้างช่องจราจรของสถานี ใช้เป็นจุดอ้างอิงผลตรวจ ไม่มีรหัสอุปกรณ์ (Asset No.) และไม่มี Serial Number; ไม่ใช่รายการใน Item Library |
| อุปกรณ์จริง (Asset) | อุปกรณ์จริงของสถานี เช่น กล้อง, NVR, เครื่องคอมพิวเตอร์, ตู้ควบคุม, เครื่องแม่ข่าย, Sensor และ Loop โดยมีทะเบียนอุปกรณ์ (Asset Register) เป็นข้อมูลอ้างอิง คำว่า Asset เป็นชื่อทางเทคนิคเดิมของอุปกรณ์จริง |
| รหัสอุปกรณ์ (Asset No.) | รหัสที่ใช้แยกอุปกรณ์แต่ละรายการในทะเบียนและผูกกับรายการตรวจ/หลักฐาน เช่น `LPR-01`; ไม่ใช่หมายเลขประจำเครื่องจากผู้ผลิต (Serial Number) |
| รายการตรวจ | จุดที่ผู้ตรวจสอบกรอกค่าตัวเลข เลือกสถานะรายการตรวจ และใส่หมายเหตุ |
| รายการหลักฐานกลาง (Evidence Catalog) | แม่แบบกลางของรายการตรวจและช่องหลักฐานทั้ง 13 PDF โดยเก็บรหัสไฟล์ ป้ายกำกับ ลำดับ ประเภท และสถานะที่พบในต้นฉบับแยกจากรอบการตรวจ |
| ช่องหลักฐานประกอบการตรวจ (Evidence Slot) | ช่องหลักฐานย่อยที่ผูกกับรายการตรวจ เช่น ภาพถ่าย วิดีโอ เอกสาร หรือข้อมูลประกอบ โดยมีสถานะและไฟล์แนบของตัวเอง |
| equipment-cleaning-v1 | นโยบายของ Snapshot รอบใหม่ที่สร้างงานทำความสะอาด 1 รายการต่ออุปกรณ์จริงที่ใช้งานอยู่ ในกลุ่ม Computer, ตู้ควบคุม, LPR, Fixed/PTZ, NVR และ Database Server |
| Cleaning stage | ช่วงหลักฐานบังคับของงานทำความสะอาด ได้แก่ `before`, `during` และ `after` โดยแต่ละช่วงเก็บภาพจริงได้ 1 ภาพและเปลี่ยนภาพได้ |
| ยังไม่ตรวจ | ค่าเริ่มต้นของรายการที่ยังไม่มีผลตรวจ |
| ปกติ | อุปกรณ์หรือรายการอยู่ในสภาพใช้งานได้ตามการตรวจเบื้องต้น |
| ชำรุด | พบปัญหาหรืออุปกรณ์ไม่พร้อมใช้งาน |
| อยู่ระหว่างรอเปลี่ยนทดแทน | พบปัญหาและมีแผน/กำลังรออะไหล่หรืออุปกรณ์ทดแทน |
| ไม่ได้ติดตั้ง | จุดนั้นไม่มีการติดตั้งอุปกรณ์ตามสภาพหน้างาน |
| ไม่เกี่ยวข้อง | รายการนี้ไม่เกี่ยวข้องกับงานหรือจุดตรวจนี้ |
| ยังไม่ได้ระบุ | ช่องหลักฐานประกอบการตรวจยังไม่ได้ระบุว่าหลักฐานครบถ้วนหรือไม่ |
| หลักฐานครบถ้วน | ช่องหลักฐานประกอบการตรวจมีข้อมูลหรือไฟล์หลักฐานครบตามจุดตรวจ |
| ก่อนทำความสะอาด / ระหว่างทำความสะอาด / หลังทำความสะอาด | ช่องภาพ 3 ช่องของอุปกรณ์จริงรายการเดียวกันในข้อมูลประจำรอบใหม่; สถานะ `complete` จะนับครบก็ต่อเมื่อมี attachment id ของภาพจริง |
| ไม่มีภาพถ่าย | ช่องนั้นไม่มีภาพถ่าย แม้ยังเก็บช่องไว้เพื่อการตรวจสอบย้อนหลัง และนับเป็นหลักฐานไม่ครบถ้วน |
| หลักฐานไม่ครบถ้วน | ยังขาดหลักฐานหรือข้อมูลของช่องนั้น และนับเป็นหลักฐานไม่ครบถ้วน |
| จัดเก็บไว้ที่เครื่องแม่ข่ายประจำสถานี | หลักฐานอยู่ที่เครื่องแม่ข่ายประจำสถานี ไม่ได้แนบไว้ในรอบนี้ และนับเป็นหลักฐานไม่ครบถ้วน |
| ค่าที่วัดได้ | ค่าตัวเลขที่ผู้ตรวจกรอกเอง หน่วยอาจต่างกันตามรายการและยังไม่บังคับใน MVP |
| ไฟล์แนบหลักฐาน | ไฟล์ที่ผูกกับรายการตรวจในรอบการตรวจนั้น เพื่อใช้อ้างอิงสภาพอุปกรณ์หรือจุดตรวจ โดยใช้ภาพถ่ายหลักฐานเฉพาะช่องภาพ |
| ข้อมูลกำกับไฟล์แนบ | ชื่อไฟล์ ชนิดไฟล์ ขนาด รหัสไฟล์ และเวลาที่แนบ ซึ่งอยู่ใน state/Snapshot ตามโหมดจัดเก็บ โดยไม่เก็บ Blob ภาพไว้ใน state หลัก |
| local-only attachment | ไฟล์จริงที่เก็บใน IndexedDB ของ browser เครื่องปัจจุบันเมื่อใช้ local mode ไม่อัปโหลดไป Backend และไม่แชร์ข้ามเครื่อง |
| server-backed attachment | ไฟล์แนบที่ส่งผ่าน API ไปยัง filesystem หรือ S3-compatible ตาม server configuration โดย client ไม่เข้าถึง object storage โดยตรง |
| เอกสารประกอบครบถ้วน | รายการในลิสมีไฟล์เอกสารประกอบที่จับคู่ได้ครบ โดยไม่ยืนยันว่าหลักฐานภายในเอกสารครบ |
| หลักฐานประกอบการตรวจครบถ้วน | ช่องภาพ/หมายเหตุ/ผลตรวจในเอกสารมีข้อมูลเพียงพอและผ่านการยืนยันจากผู้รับผิดชอบหน้างาน |
| attachment manifest | ตารางการจับคู่ระหว่างรหัสรายการ ไฟล์ต้นฉบับ ไฟล์ในแพ็กเกจ และสถานะแยกของเอกสารประกอบกับหลักฐานประกอบการตรวจ |
| checklist-master-v3-boq-evidence | แม่แบบประวัติเดิม (v3) ที่แสดงรายการและช่องหลักฐานตามลำดับ PDF ทั้ง 13 หมวด; ใช้อ่านข้อมูลประจำรอบเดิม ไม่ใช่แม่แบบปัจจุบัน |
| displayLabel | ข้อความที่ผู้ใช้เห็นใน Checklist ซึ่งแก้ผ่าน Master copy ได้โดยไม่เปลี่ยนรหัสรายการ |
| sourceLabel | ข้อความอ้างอิงจากช่องใน PDF ต้นฉบับ ใช้สำหรับ audit และไม่เปลี่ยนตาม displayLabel |
| checklist-master-v4-asset-mapped | แม่แบบเดิม (v4) ที่ผูก `3.1` กับ LANE Asset; ใช้เปิดข้อมูลประจำรอบเดิมโดยไม่แปลงข้อมูลย้อนหลัง |
| checklist-master-v5-system-mapped | แม่แบบปัจจุบัน (v5) ที่ผูก `3.1` กับ Lane topology และแยก Lane ออกจากทะเบียนอุปกรณ์จริง (Asset Register) |
| copyRevision | รุ่นของชุดข้อความที่ถูกเก็บไว้ใน Inspection Snapshot ของรอบนั้น |
| ชุดข้อความมาตรฐานกลาง | ชุดชื่อหมวด ชื่อรายการ หน่วย และคำอธิบายที่แก้จากหน้า `สถานีและอุปกรณ์` และเก็บใน browser เครื่องปัจจุบัน |
| ข้อมูลลงนามรายงาน | ข้อมูลผู้จัดทำรายงาน ผู้ตรวจสอบรายงาน ผู้มีอำนาจลงนาม และวันที่ลงนาม ใช้ประกอบการลงนามในรายงานเท่านั้น ไม่ใช่ขั้นตอนการอนุมัติของระบบ |
| local-first | โหมดที่บันทึกข้อมูลใน browser เครื่องปัจจุบันก่อน ยังไม่ส่งไปยังเครื่องแม่ข่าย; เป็นค่า default สำหรับ local development ไม่ใช่ข้อกำหนดของ server mode |
| central persistence | แหล่งเก็บข้อมูลส่วนกลางของ server mode ที่คุม state, Snapshot, evidence metadata, station scope และการกู้คืนผ่าน API |
| offline draft | ข้อมูลแก้ไขที่ส่งเข้า central persistence ไม่สำเร็จและรอส่งซ้ำ; ไม่ใช่ Snapshot ที่ปิดรอบแล้ว |
