# การจัดเก็บไฟล์หลักฐาน

ไฟล์ใหม่เก็บใน `data/attachments/stations/<ชื่อสถานีที่ปรับให้ปลอดภัย>--<stationId>/<year>/rounds/<roundId>/<kind>/<uuid>.<ext>` โดย kind เป็น `inspection/originals`, `vehicle-api/originals` หรือ `vehicle-api/webp` ปีมาจากเวลาสร้างไฟล์ใน Asia/Bangkok ไม่เปลี่ยนตามการแก้วันที่ตรวจ ส่วนท้าย `stationId` ทำให้แยกสถานีที่ชื่อซ้ำกันได้แน่นอน

เมื่อสร้างสถานี ระบบสร้าง `stationCode` จากรหัสภายในของสถานีให้ก่อน ผู้ใช้แก้เป็นรหัสทางการได้ รหัสเก่าและรหัสใน Snapshot เดิมไม่เปลี่ยน `stationId` และรหัสรอบเป็นชื่อคงที่ รายงานและ Snapshot อ้าง attachment ID เดิม ไฟล์ที่หลายรอบใช้ร่วมกันอยู่ตำแหน่งเดิมของเจ้าของไฟล์ ไม่สร้างสำเนาตามจำนวนรอบ

เมื่อแก้ชื่อสถานี ระบบคัดลอกไฟล์ไปโฟลเดอร์ชื่อใหม่และตรวจขนาดกับ SHA-256 ก่อนอัปเดต `attachments.storage_name` ในธุรกรรมเดียวกับข้อมูลสถานี เมื่อบันทึกสำเร็จจึงเอาไฟล์จากตำแหน่งเก่าออก หากตรวจไฟล์ไม่ผ่าน ระบบยกเลิกการเปลี่ยนชื่อและเก็บไฟล์ต้นฉบับไว้

ไฟล์ที่รู้ด่านแต่ไม่รู้รอบอยู่ใต้ `stations/<ชื่อด่าน>--<stationId>/unassigned/<year>/` ไฟล์ที่ไม่รู้ด่านอยู่ใน `unassigned/<year>/` ไม่เดาเจ้าของจากชื่อไฟล์ และไม่ลบไฟล์เพียงเพราะรอบปัจจุบันไม่ได้ใช้งาน ระบบยังอ่านชื่อไฟล์เก่าแบบไม่มีโฟลเดอร์ได้

## เครื่องมือย้ายข้อมูล

ใช้ `node --env-file=.env tools/organize_attachments.mjs <mode> <outputDir> [stationId]`

- `plan`: ตรวจ metadata ไฟล์ ขนาด SHA-256 และการอ้างอิงจากข้อมูลปัจจุบันกับประวัติที่เก็บไว้ แล้วเขียน manifest โดยยังไม่ย้ายไฟล์
- `apply`: คัดลอก ตรวจเนื้อหา แล้วเปลี่ยน storage_name ทีละไฟล์ ทำซ้ำได้; เมื่อกำหนด stationId จะทำเฉพาะด่านสำหรับทดลองก่อนขยาย
- `verify`: ตรวจตำแหน่งในฐานข้อมูลกับเนื้อหาไฟล์ และรายงานว่า app_state เปลี่ยนจากบัญชีก่อนย้ายหรือไม่
- `archive-legacy`: หลังตรวจผ่าน ย้ายไฟล์จากตำแหน่งเก่าไป `<outputDir>/legacy-flat/` เพื่อเก็บคืน โดยไม่ลบต้นฉบับที่ตำแหน่งใหม่หรือสำเนาสำรอง
- `rollback`: คืนไฟล์เก่าจาก legacy-flat ถ้าจำเป็น และคืน storage_name เฉพาะรายการที่ยังตรงกับ manifest ไม่คืนทั้งฐานข้อมูลทับงานใหม่

ก่อน `apply`, `archive-legacy` หรือ `rollback` ต้องหยุดบริการ และมี `<outputDir>/backup.json` ระบุ `database` เป็นไฟล์สำรองฐานข้อมูลกับ `attachments` เป็นโฟลเดอร์สำรองรูปจากชุดเดียวกัน เครื่องมือปฏิเสธการย้ายเมื่อบริการที่ `CHECKLIST_MIGRATION_SERVICE_URL` (ค่าเริ่มต้น http://127.0.0.1:5220) ยังตอบ หรือมีข้อผิดพลาดในบัญชีไฟล์ ต้องยืนยันบริการจริงหยุดด้วย ไม่เปลี่ยน URL เพื่อหลีกเลี่ยงขั้นนี้

หากข้อมูลกลางเปลี่ยนระหว่างสำรวจและย้าย เครื่องมือจะหยุด ให้สร้างบัญชีใหม่หลังหยุดบริการและสำรองข้อมูลใหม่ การย้อนกลับตัวโปรแกรมต้องใช้รุ่นที่อ่านโฟลเดอร์ย่อยได้ เพราะรูปที่เพิ่มหลังเปิดใช้งานอาจอยู่ตำแหน่งใหม่แล้ว

## ย้ายชื่อโฟลเดอร์สถานี

ใช้ `node --env-file=.env tools/rename_station_attachment_folders.mjs <plan|apply|verify> <outputDir> [stationId]` หลังระบบใช้โครงสร้างเดิมตาม station ID อยู่แล้ว `plan` บันทึกจำนวนไฟล์และ SHA-256 พร้อมสถานะข้อมูลส่วนกลาง `apply <outputDir> <stationId>` ใช้ทดลองทีละสถานีก่อนได้ แล้วจึงใช้ `apply <outputDir>` เพื่อทำทั้งหมด `verify` ตรวจตำแหน่งในฐานข้อมูลและเนื้อหาไฟล์โดยไม่แก้ Snapshot หรือประวัติ

ก่อน `apply` ให้สำรองฐานข้อมูลและไฟล์แนบครบชุด ตรวจว่าชุดสำรองมี manifest, dump และดัชนีแฮช แล้วใส่พาธใน `<outputDir>/backup.json` จากนั้นหยุดบริการและยืนยันว่า `/health` ไม่ตอบ เครื่องมือไม่เริ่มหากไฟล์ขาด แฮชผิด หรือมีไฟล์ที่ไม่ตรงกับ metadata

## ชุดสำรองและกู้คืน

`node --env-file=.env tools/backup_postgres.mjs` สร้างชุดใหม่ในโฟลเดอร์ชั่วคราว ตรวจ dump ด้วย `pg_restore --list` และตรวจขนาดกับ SHA-256 ของไฟล์แนบก่อนย้ายชุดไปชื่อจริง ชุดที่บันทึก `retentionGroup: checklist-rolling-v1` เท่านั้นที่ถูกจำกัดให้เหลือ 3 ชุดล่าสุด ชุดเดิมและโฟลเดอร์สำรองไม่สมบูรณ์ไม่ถูกลบโดยนโยบายนี้

สำรองเพื่อใช้ก่อนย้ายโฟลเดอร์ข้อมูล ให้ตั้ง `CHECKLIST_BACKUP_PRESERVE_ATTACHMENT_LAYOUT=true` และเก็บชุดไว้ในพื้นที่ staging แยกจาก `backups` ชุดนี้คงพาธที่ฐานข้อมูลใช้อยู่ทุกพาธ รวมกรณีที่สถานีมีทั้งโฟลเดอร์เดิมกับโฟลเดอร์ชื่อใหม่ เมื่อย้ายไฟล์จริงและตรวจผ่านแล้วจึงสร้างชุดสำรองปกติที่จัดโฟลเดอร์ตามชื่อสถานี

โฟลเดอร์สถานีในสำรองใช้ชื่อสถานี ณ เวลาสำรอง ส่วน `attachmentRestoreMap` เก็บชื่อโฟลเดอร์และ prefix ที่ฐานข้อมูลในชุดนั้นอ้างถึง ให้กู้ไฟล์แนบไปยังโฟลเดอร์ที่ยังไม่มีด้วย `node tools/restore_backup_attachments.mjs <backupDir> <newDirectory>` ก่อนกู้ระบบในพื้นที่ทดสอบ แผนที่นี้รองรับ dump เก่าที่อ้าง `stations/<stationId>/` ด้วย การเปลี่ยนชื่อชุดเก่าทำด้วย `node tools/migrate_backup_station_folders.mjs <plan|apply|verify>` ชุดไม่สมบูรณ์จะไม่ถูกแตะ

ก่อนเปิดบริการตรวจ API การอ่านไฟล์ รายงานและประวัติที่มีสิทธิ์ รวม /health, /ready และไฟล์แอปที่ให้บริการ เก็บ manifest, journal และผล verify ไว้คู่กับสำรองข้อมูล ห้ามลบสำเนาเก่าหรือไฟล์รอจัดรอบโดยอัตโนมัติ

## การทดสอบ

`tools/test_attachment_organization.mjs` ตรวจโฟลเดอร์ย่อย ไฟล์เก่า การไม่เขียนทับ ชื่อไทย และการป้องกันตำแหน่งออกนอก root รวม junction; `tools/test_attachment_organization_api.mjs` ตรวจ API จริงกับพื้นที่ชั่วคราว; `tools/test_attachment_migration.mjs` ใช้ schema ทดสอบแยกจากข้อมูลจริง ตรวจรูปใช้ร่วม ประวัติ ไฟล์เสีย การทำซ้ำ การเก็บคืน และย้อนกลับ; `tools/test_station_attachment_migration.mjs` ตรวจย้ายชื่อพร้อมการตรวจแฮช; `tools/test_backup_retention.mjs` ตรวจชุดล้มเหลว การเก็บชุดเก่า และกู้คืนตำแหน่ง attachment

การแบ่งโฟลเดอร์ไม่ลดพื้นที่รวม สำเนาสำรองและ legacy-flat ยังใช้พื้นที่เพิ่ม และไม่เปลี่ยนนโยบายลบรอบหรือหลักฐานตาม ADR 0006
