# ตรวจเทียบรายการตรวจกับเอกสาร PDF ต้นทาง

วันที่ตรวจ: 15 กันยายน 2569

หมายเหตุสถานะ: เอกสารนี้เป็นผลเทียบเชิงนโยบาย ณ วันที่ระบุ ตัวเลขโปรไฟล์ตัวอย่าง 97/128 ด้านล่างเป็น historical sample ไม่ใช่ baseline ปัจจุบัน; การตรวจซ้ำวันที่ 21 กันยายน 2569 ผ่านชุด regression 42/42 และยืนยันกติกา WIM Electronics/Vehicle API ตาม source ปัจจุบัน

## ขอบเขตและแหล่งข้อมูล

- เอกสารต้นทางใน `output/pdf/1.1.pdf` ถึง `output/pdf/7.1.pdf` รวม 13 หมวด
- รายการหลักฐานและกติกาการสร้างรอบใน `src/domain/evidence-checklist.js`
- กติกาการผูกอุปกรณ์จริงและการทำความสะอาดใน `docs/attachment-audit.md` และ `docs/station-checklist-controls.md`

## ข้อสรุป

โครงสร้างหมวดหลักตรงกับเอกสารทั้ง 13 หมวด แต่รายการตรวจที่ผู้ตรวจเห็นในรอบใหม่เป็นรายการที่คำนวณจากอุปกรณ์จริงและนโยบายปัจจุบัน ไม่ใช่การคัดลอกทุกช่องจาก PDF แบบหนึ่งต่อหนึ่ง

ค่าที่ตรวจจากโปรไฟล์สถานีตัวอย่างปัจจุบัน:

- แม่แบบหลักระดับสถานี: 13 หมวด / 44 รายการ
- แม่แบบหลักฐานตาม PDF: 13 หมวด / 170 รายการก่อนใช้นโยบายรอบใหม่
- รอบใหม่ของโปรไฟล์ตัวอย่าง: 97 รายการตรวจ / 128 evidence slots
- โปรไฟล์ตัวอย่างมีอุปกรณ์ 21 รายการ, ระบบ 9 รายการ และ 3 Lane

ดังนั้นการเห็นจำนวนไม่เท่ากับ 170 ไม่ได้แปลว่าระบบนับผิดทันที แต่ต้องแยกว่าเป็น “รายการหลักฐานกลาง”, “รายการตรวจที่เปิดใช้ในสถานี” หรือ “รายการใน Snapshot ของรอบนั้น”

## จุดที่ไม่ควรถือว่าเป็นความผิดพลาด

สถานะใน PDF เช่น `ไม่มีภาพถ่าย`, `หลักฐานไม่ครบ`, `ไม่ได้ติดตั้ง` และ `จัดเก็บไว้ที่เครื่องแม่ข่าย` ถูกเก็บเป็นสถานะที่พบจากเอกสารต้นทาง ไม่ได้ถูกนำมาเป็นคำสั่งใหม่ให้รอบถัดไปต้องผ่านหรือสร้างช่องเพิ่ม ตามที่ระบุใน `docs/attachment-audit.md`

การเปลี่ยนจากช่องทำความสะอาดรวมใน PDF เป็นช่องต่ออุปกรณ์จริง 3 ช่วงก็เป็นนโยบายปัจจุบันที่ตั้งใจทำ เพื่อไม่ให้ตรวจรวมจนไม่รู้ว่าอุปกรณ์ใดถูกทำความสะอาดแล้ว

## ผลการตัดสินใจเชิงธุรกิจ

1. อนุมัติให้ตัดรายการตรวจวิดีโอทั้งหมดออกจากแม่แบบที่ใช้งานปัจจุบัน ครอบคลุม `2.3`, `3.1/3.2`, `6.1` และ `7.1` รายการวิดีโอเดิมยังคงมีรหัส migration เพื่อป้องกันข้อมูลเก่าหลงกลับเข้าระบบ แต่ไม่ถูกสร้างเป็นรายการใหม่
2. NVR ยังควรตัดสินใจเพิ่มเติมว่าต้องบันทึกตัวเลข `จำนวน HDD เสีย` และ `จำนวนวันย้อนหลังได้` เป็นค่าที่กรอก/ตรวจรับหรือไม่ หากใช่ควรเพิ่มช่องตัวเลขแยก ไม่ควรใช้ภาพอย่างเดียว
3. จำนวน SENSOR/LOOP ของแต่ละสถานีต้องยึดทะเบียนอุปกรณ์จริง หากเอกสารสถานีจริงมี 12 SENSOR/6 LOOP แต่ทะเบียนมีน้อยกว่านั้น แปลว่าต้องเติมทะเบียนสถานี ไม่ใช่เพิ่มรายการตรวจแบบตายตัว
4. Switching DC ที่มีหลาย Output ต้องลงทะเบียนแรงดันใน `outputVoltages` ของอุปกรณ์ให้ครบ เช่น `[12, 24, 48]` จึงจะสร้างรายการตรวจแยกตามแรงดันครบ ไม่ควรสมมติจากชื่ออุปกรณ์อย่างเดียว

## ข้อสรุปสำหรับการอนุมัติรายการ

สถานะปัจจุบันคือ **รายการวิดีโอถูกตัดออกจากรายการตรวจปัจจุบันแล้ว** และเพิ่มการตรวจ NVR เชิงตัวเลข, cleaning พื้นที่ และการสร้าง WIM Electronics ตาม Asset Register แล้ว จำนวนอุปกรณ์จริงต่อสถานียังคงเป็นตัวกำหนดจำนวนรายการตรวจ โดยเฉพาะ Switching DC ที่ต้องลงทะเบียน `outputVoltages` ให้ครบ

ส่วนที่ตรงแล้วคือโครงสร้างหมวดหลักและรายการอุปกรณ์/ไฟฟ้าหลักของ WIM Electronics การตรวจโค้ดปัจจุบันยืนยันว่าแม่แบบหลักฐาน, รายการรอบใหม่ และรายการหลักฐานที่คำนวณของโปรไฟล์ตัวอย่างไม่มี `fieldType: "video"` แล้ว การเปลี่ยนครั้งนี้ไม่ลบข้อมูลประวัติหรือ Snapshot เดิม
