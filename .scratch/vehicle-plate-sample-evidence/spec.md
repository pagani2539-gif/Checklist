# ชุดคะแนนตรวจป้ายทะเบียนกลางวัน/กลางคืนและการคัดหลักฐาน

Status: ready-for-human
Updated: 2026-10-05

## กติกาที่ผู้ใช้อนุมัติ

### ขอบเขต

- ใช้เฉพาะงานตรวจป้ายทะเบียนกลางวันและกลางคืน แยกชุดกันตามเวลาเหตุการณ์ในเขตเวลาไทย
- ไม่เปลี่ยนกติกาคัดแยกประเภทรถ
- API ปัจจุบันดึงข้อมูลก่อนแล้วจึงคัดช่วงเวลาในเครื่อง จึงทำขั้นคัดหลักฐานหลังดึงและก่อนล็อกชุดคะแนน

### ข้อมูลต้นทางและความพร้อมคิดคะแนน

1. เก็บรายการจาก API ทุกคันไว้ในข้อมูลต้นทาง แล้วให้ผู้ตรวจดูภาพและคัดรายการทีละคันก่อนสร้างชุดคะแนน
2. ผู้ตรวจเลือก “พร้อมคิดคะแนน” เมื่อภาพที่เปิดดูได้ยืนยันทั้งเลขทะเบียนและจังหวัดจากรถคันเดียวกัน ไม่พิจารณาจากค่าที่ API ส่งว่ามีหรือถูกหรือไม่
3. ถ้า API ไม่มีเลขทะเบียนหรือจังหวัด หรืออ่านค่าไม่ตรงกับภาพ ให้รายการอยู่ในคะแนนและนับเป็นอ่านไม่ถูก ผู้ตรวจบันทึกเลขทะเบียนจริงและจังหวัดจริงจากภาพ
4. ถ้าไม่มีภาพจากต้นทาง เปิดภาพไม่ได้หลังลองใหม่ ป้ายถูกบังหรือเห็นไม่ครบ ภาพไม่ชัดจนยืนยันข้อมูลจริงไม่ได้ หรือภาพเป็นรถคนละคัน ให้คัดออกพร้อมเหตุผล รายการยังอยู่ในข้อมูลต้นทางและภาคผนวก แต่ไม่เข้าเศษหรือตัวหาร
5. ระบบไม่เดาความชัดจากข้อความ ช่องข้อมูล หรือ URL ภาพ ผู้ตรวจเป็นผู้ตัดสินจากภาพที่เปิดได้จริง
6. ทุกแถวต้องมีสถานะก่อนล็อกชุด การคัดออกเก็บเหตุผล หมายเหตุ ผู้บันทึก และเวลา

### การสุ่มและล็อก

- ใช้วิธีสุ่มกระจายตามเวลาเดิมจากรายการ “พร้อมคิดคะแนน” เท่านั้น เป้าหมาย 100 คันต่อช่วงกลางวันและกลางคืน
- ถ้ามีรายการพร้อมคิดคะแนนน้อยกว่า 100 ให้ล็อกเท่าที่มีและตรวจได้ แต่ผลของช่วงนั้นต้องเป็น “ข้อมูลไม่พอทดสอบ” และห้ามรายงานว่าผ่าน
- เมื่อเริ่มตรวจคะแนนแล้ว ห้ามเปลี่ยนสมาชิกของชุดที่ล็อก หากต้องเปลี่ยนให้สร้างชุดใหม่ตามทางเปลี่ยนชุดที่มีอยู่

### คะแนนและรายงาน

- คำนวณความถูกต้องเป็น อ่านถูก ÷ (อ่านถูก + อ่านไม่ถูก) และเทียบเกณฑ์ 80% จากค่าก่อนปัดเศษ
- แสดงคะแนนทศนิยมสองตำแหน่ง ตัวอย่าง 79.50% ไม่ผ่านเกณฑ์ 80% แม้การปัดเป็นจำนวนเต็มจะแสดง 80%
- “ตรวจไม่ได้” ไม่เข้าเศษหรือตัวหาร แต่ทำให้ผลยังไม่สมบูรณ์และห้ามสรุปว่าผ่าน
- รายงานแยกยอดข้อมูลต้นทาง ยอดพร้อมคิดคะแนน จำนวนที่เลือกเข้าชุด จำนวนคัดออก และผลคะแนน
- มีภาคผนวกรายคันของรายการคัดออกพร้อมเหตุผลและข้อมูลผู้บันทึก แยกจากผลคะแนน

## ข้อมูลและความเข้ากันได้

- `sourceRows` เก็บข้อมูลต้นทางทั้งหมดและสถานะคัดเลือก ส่วน `rows` หลังล็อกเก็บเฉพาะรายการในชุดคะแนน
- ชุดคะแนนใหม่ใช้รุ่น `plate-evidence-v2` และเก็บรหัสรายการที่เลือกไว้ใน Snapshot
- Snapshot เก่าที่ไม่มีรุ่นกติกาใหม่นี้ต้องแปลผลด้วยกติกาเดิม ห้ามตีความใหม่หรือแก้ประวัติเดิม
- ใช้การบันทึกกลางและรหัสภาพแนบเดิม ไม่ลบข้อมูลต้นทางหรือ Snapshot

## การตรวจรับ

- สถานะคัดเลือก ผู้บันทึก และเวลายังอยู่หลังบันทึก โหลดซ้ำ และสร้างรายงาน
- ภาพชัดแต่ API ไม่มีเลขหรือจังหวัด: เข้าเกณฑ์เลือกชุดและทำเครื่องหมายอ่านไม่ถูกได้ พร้อมบันทึกค่าจริงทั้งเลขทะเบียนและจังหวัด
- ไม่มีภาพหรือยืนยันค่าจริงจากภาพไม่ได้: ไม่เข้าเศษหรือตัวหาร และอยู่ในภาคผนวกพร้อมเหตุผล
- กลางวัน/กลางคืนแยกชุดกัน, ชุดล็อกสุ่มไม่ได้หลังเริ่มตรวจ, และรายการคัดออกยังอยู่ในข้อมูลต้นทาง
- จำนวนพร้อมคิดคะแนนต่ำกว่า 100 ให้รายงาน “ข้อมูลไม่พอทดสอบ” และห้ามผ่าน
- ตรวจขอบเกณฑ์ 79.50% เทียบเกณฑ์ 80% โดยไม่ใช้ค่าที่ปัดเศษ
- รายงานใหม่ใช้กติกา v2 ส่วน Snapshot เก่าใช้กติกาเดิม

## บันทึกที่มาของข้อกำหนด

2026-10-04: ผู้ใช้กำหนดกติกาใหม่ให้คัดข้อมูลหลังดึง API แต่ก่อนล็อกชุดคะแนน โดยแยกข้อมูลต้นทางออกจากชุดคะแนน และให้คัดรายการที่ภาพไม่ยืนยันเลขทะเบียนกับจังหวัดได้ออกพร้อมเหตุผล ข้อกำหนดนี้แทนข้อเสนอเดิมที่ขัดกัน
