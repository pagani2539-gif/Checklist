# สรุปละเอียดผลตรวจรถ

Status: ready-for-human

เพิ่มอันดับจังหวัด/ประเภทรถและผลแยกกลุ่ม คู่ที่อ่านผิด ช่องทาง/เวลา ในรายงานเดิมทั้งหน้าจอและ PDF A4/พรีเซนต์ ใช้รายการชุดคะแนนเดิม แยก API/ค่ายืนยัน ไม่เปลี่ยน persisted state, Snapshot, attachment หรือกติกาคะแนน

ทดสอบข้อมูลเก่า ยืนยันบางส่วน ข้อมูลหาย ขอบเวลาไทย อันดับร่วม pagination isolation ของระบบ/ช่วง และยอดตรงกับรายงานเดิม

## Validation

- `node tools/test_vehicle_review_analytics.mjs`
- Existing Snapshot evidence, reason grouping, report model, progress, day/night and PDF tests
- Browser checks and export artifacts: `output/playwright/vehicle-analytics/`

## ผลตรวจรับ 2026-10-10

- ทำครบอันดับ/ผลแยกกลุ่ม คู่ผิด ช่องทาง/เวลา และ PDF จากตัวคำนวณเดียวกัน
- ปรับคำให้แยกข้อมูลที่ระบบอ่านได้กับข้อมูลที่ผู้ตรวจยืนยัน และอธิบายฐานเปอร์เซ็นต์ ลดหัวข้อซ้ำ รวมตารางเฉพาะเมื่อค่าตรงกันทุกรายการ งดตารางกลางวันซ้ำสำหรับชุดคัดประเภทที่มีแต่กลางวัน
- การทดสอบการคำนวณและรายงานเดิมผ่าน ครอบคลุมข้อมูลเก่า ยืนยันบางส่วน สถานะทั้งหมด ข้อมูลหาย อันดับร่วม คู่ค่าเดิม และชุดว่าง
- ตรวจเว็บที่ให้บริการจริงพอร์ต 5220 ด้วยข้อมูลจำลองในเบราว์เซอร์แยก ไม่เขียนข้อมูลส่วนกลาง: อันดับ 10/ดูทั้งหมด เปิดหลักฐาน เปลี่ยนช่วงเวลา มือถือ/แท็บเล็ต และสีสว่าง/มืดผ่าน
- ส่งออก PDF ป้ายทะเบียน A4 27 หน้า/พรีเซนต์ 29 หน้า และประเภท A4 16 หน้า/พรีเซนต์ 18 หน้า ตรวจภาพหน้าตารางของทั้งสี่ไฟล์แล้ว แถวท้ายแสดงครบ ไม่มีการเขียนข้อมูลระหว่างทดสอบ
- สร้างด้วย Vite ผ่าน และตรวจ HTML/CSS/JavaScript ที่พอร์ต 5220 ตรงกับไฟล์ที่สร้าง พร้อม health/ready ผ่าน
- คำสั่ง build ปกติยังติดเงื่อนไข select เดิมใน ImageAnnotationEditor.jsx ซึ่งอยู่นอกงานนี้ ใช้การสร้าง Vite โดยตรง
- ยังต้องให้ผู้ใช้ตรวจความเหมาะสมกับรอบตรวจจริงของสถานี การตรวจเบราว์เซอร์และตัวอย่าง PDF ใช้ข้อมูลจำลอง ไม่ใช่ผลยืนยันรอบจริง

## ปรับแบ่งหน้าตามพื้นที่จริง 2026-10-10

- ยกเลิกจำนวนแถวตายตัวในข้อมูลสรุป วัดความสูงแถวหลังโหลดแบบอักษรและรูป พร้อมพื้นที่หัวเรื่อง คำอธิบาย หัวตาราง และท้ายหน้า
- จัดหน้าแบบเดียวกันในรายงานชุดทดสอบและรายงานรวม แยกขนาด A4/พรีเซนต์ รอจัดหน้าก่อนพิมพ์หรือดาวน์โหลด และหยุดส่งออกเมื่อแถวเดียวสูงเกินหน้า
- ทดสอบการจัดแถว 1/6/7/13/50 รายการ ความสูงต่างกัน ขอบพอดีหน้า ชุดว่าง และแถวเกินหน้า ผ่าน
- เบราว์เซอร์: 13 จังหวัดชื่อปกติอยู่หน้าเดียว; ชื่อยาว 13 กลุ่มแบ่ง 12+1 และ 50 กลุ่มแบ่ง 12+12+12+12+2 แถวเกินหน้าถูกแจ้งและหยุดดาวน์โหลดจริง ไม่เขียนข้อมูลส่วนกลาง
- รายงานรวม A4/พรีเซนต์และรูปแบบหน้าพิมพ์ตรวจแล้ว ลำดับและจำนวนแถวตรงกับข้อมูลต้นทางทุกหัวข้อ ไม่มีแถวซ้ำหรือทับท้ายหน้า
- แก้การแปลงตารางเป็นภาพ PDF ที่เคยนำความสูงรวมคำอธิบายไปยืดแถว ใช้กฎความสูงอัตโนมัติในภาพส่งออก โดยไม่แก้ตารางต้นฉบับหรือข้อมูลบันทึก
- ไฟล์ PDF ตัวอย่างชุดป้ายทะเบียนเหลือ A4 20 หน้า/พรีเซนต์ 22 หน้า และประเภท A4 12 หน้า/พรีเซนต์ 16 หน้า จากข้อมูลจำลองเดิม
- ไฟล์ตรวจเฉพาะตารางสรุปของรายงานรวมแบบพิมพ์อยู่ที่ combined-analytics-native.pdf รวม 15 หน้า ตรวจรูปหน้าแสดงประเภทรถครบแล้ว

## ปรับลำดับผลตรวจ 2026-10-10

- แต่ละระบบเรียงภาพรวมป้ายทะเบียน/ประเภทก่อน สาเหตุทุกช่วงเวลา คู่ผิด อันดับจังหวัด/ประเภท ช่องทาง ช่วงเวลาและชั่วโมง แล้วจึงหลักฐานผิด/ตรวจไม่ได้/รอตรวจ/ถูก และรายการคัดออกท้ายสุด
- ใช้ตัวเรียงร่วมกับรายงาน Snapshot ชุดทดสอบและรายงานรวม ภาพรวมบนหน้าจออยู่ก่อนตารางวิเคราะห์ด้วย
- ภาพรวมแสดงยอดชุดตรวจและสัดส่วน 4 สถานะก่อนคะแนน สีแยกกลุ่มและมีข้อความ/จำนวน/เปอร์เซ็นต์ประกอบ คะแนนและฐานคำนวณเดิมไม่เปลี่ยน
- เพิ่ม test_vehicle_report_order.mjs ครอบคลุมหลายระบบ บริบทป้าย/ประเภท ทุกช่วงเวลา ข้อมูลเวลาหาย ชุดว่าง และทุกรายการในหลักฐานปรากฏครบครั้งเดียว โดยข้อมูลต้นทางไม่เปลี่ยน
- ตรวจเบราว์เซอร์ทั้ง A4/พรีเซนต์และมือถือสีมืดด้วยข้อมูลจำลอง สัดส่วนรวม 100% คะแนนตรงเดิม ลำดับตรงกับตัวสร้างรายงาน ไม่มีการเขียนข้อมูลส่วนกลาง
- ส่งออกและตรวจภาพหน้าแรกของ PDF ทั้งสี่รูปแบบ พร้อมปรับพื้นที่หน้าพรีเซนต์ให้คำอธิบายคะแนนไม่ทับท้ายหน้า

## คืนเปอร์เซ็นต์และคำมาตรฐาน 2026-10-11

- ช่องหกเหลี่ยมกลับมาแสดงความถูกต้องตามเกณฑ์ ใช้ฐานถูกต้อง + ไม่ถูกต้องและการปัดทศนิยมเดิม แยกไม่มีผลตัดสินเป็น — ไม่ใช้ 0% แทนข้อมูลขาด
- ปรับคำสี่สถานะ ข้อมูลจากระบบ/ผู้ตรวจสอบยืนยัน และหน่วยรายการในส่วนแสดงผลร่วม โดยไม่แก้รหัสหรือข้อมูลบันทึก
- แก้ข้อความเบียดในหกเหลี่ยม: แบ่งความถูกต้อง/ตามเกณฑ์เป็นสองบรรทัด วางจำนวนถูกต้องและตัดสินผลแล้วใต้กรอบ และตัดยอดรวมที่แสดงซ้ำในส่วนคะแนน
- ทดสอบ score, order, analytics, snapshot evidence, reasons, hex, measured pagination, PDF dimensions, report model, total accuracy และ threshold boundaries ผ่าน
- ตรวจเบราว์เซอร์ข้อมูลจำลอง Snapshot ปิดรอบ ทั้ง A4/พรีเซนต์และมือถือสีมืด พร้อมรายงานรวม/การพิมพ์ แถวครบ ลำดับเดิม ไม่มีข้อความคะแนนทับท้ายหน้า ไม่มีการเขียนข้อมูลส่วนกลาง
- ส่งออก PDF จริงและเปิดตรวจภาพหน้าแรกครบ 4 ชุด: ป้ายทะเบียน A4 20 หน้า/พรีเซนต์ 23 หน้า ประเภท A4 12 หน้า/พรีเซนต์ 16 หน้า; ตรวจพื้นที่ตารางทุกหน้าในการส่งออก
- Vite build ผ่านและไฟล์ที่ให้บริการ 5220 ตรงกับ build, health/ready ผ่าน; npm build ปกติยังมีข้อขัดข้องเดิมเรื่อง native select ใน ImageAnnotationEditor
- การตรวจรอบสถานีจริงที่ต้องเข้าสู่ระบบยังไม่ได้ดำเนินการ ข้อมูลต้นทางและ PDF เดิมไม่เปลี่ยน ต้องส่งออกใหม่เพื่อเห็นรูปแบบนี้

## แก้ฐานความถูกต้องตามคำยืนยัน 2026-10-11

- ผู้ใช้ยืนยันว่ารายการไม่สามารถตรวจสอบได้ต้องนับในฐานความถูกต้อง ตรวจพบรายงานต้นทาง vehicle-report.js ใช้ถูกต้อง/ทั้งหมดเมื่อมีผลบันทึกแล้ว ไม่ใช้ถูกต้อง/(ถูกต้อง+ไม่ถูกต้อง)
- แก้ getVehicleReportScore ให้ตรงสูตรต้นทางทั้งหมด รวมรายการรอตรวจในฐานตามกติกาเดิม แต่รอตรวจทั้งหมด/ชุดว่างยังไม่มีคะแนน; ตรวจสอบไม่ได้ทั้งหมดเป็น 0.00%
- ตัวเลขกรอบและส่วนคะแนนใช้สองทศนิยมเหมือนรายงานต้นทาง จำนวนประกอบและฐานอธิบายยอดทั้งหมด; กรณีภาพผู้ใช้ 105/108 =97.22%, 105/111=94.59%
- เพิ่มทดสอบตัวเลขจากภาพจริงและอัปเดตการตรวจเบราว์เซอร์ข้อมูลจำลองเป็น25.00% (6/24) ผ่าน A4/พรีเซนต์/มือถือ ไม่มีส่วนคะแนนทับท้ายหน้า; ทดสอบ total accuracy, threshold, order และ build ผ่าน ไฟล์5220ตรงกับ build
- เป็นการแก้การแสดงผลให้ตรงคะแนนเดิม ไม่เปลี่ยนผลบันทึก Snapshot ประวัติหรือ API; บันทึกหัวข้อก่อนหน้าที่กล่าวถึงฐานถูกต้อง+ไม่ถูกต้องถูกแทนที่ด้วยหัวข้อนี้
