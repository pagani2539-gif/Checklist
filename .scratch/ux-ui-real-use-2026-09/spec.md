# แผนทดสอบใช้งานจริงและตรวจ UX/UI ทั้งระบบ

Type: quality
Status: ready-for-human
Blocked by: isolated test environment and participant sessions

## เป้าหมาย

ตรวจเส้นทางงานหลักของ Checklist Operations Hub ตั้งแต่จัดการผู้ใช้ สัญญา
สถานี และอุปกรณ์ ไปจนถึงตรวจหน้างาน ปิดรอบ ดูรายงาน และสร้างฉบับแก้ไข
บันทึกปัญหา CSS ส่วนประกอบ ข้อความ และความเข้าใจขั้นตอน พร้อมภาพและทางทำซ้ำ

## ขอบเขตความปลอดภัย

- ใช้เฉพาะฐานข้อมูลและพื้นที่เก็บไฟล์ของระบบทดสอบที่ยืนยันแล้วว่าแยกจากระบบจริง
- ใช้ข้อมูลจำลองเท่านั้น รวมถึงบัญชี ผู้รับจ้าง สัญญา งวด สถานี และหลักฐาน
- Vehicle API ใช้ปลายทางทดสอบหรือข้อมูลตัวอย่าง ห้ามส่งข้อมูลจริง
- ห้ามใช้ค่าเชื่อมต่อฐานข้อมูลจาก `.env` เพื่อสร้าง แก้ ลบ หรือปิดรอบทดสอบ
- เก็บ Snapshot และประวัติเดิมไว้ครบ ตรวจเฉพาะการแสดงผลและผลการทำงาน

## ผู้ทดสอบและอุปกรณ์

- เจ้าหน้าที่หน้างานอย่างน้อย 2 คน
- แอดมินอย่างน้อย 2 คน
- หัวหน้าอย่างน้อย 2 คน
- มือถือ Android และ iPhone จริงสำหรับทดสอบการแตะ การหมุนจอ กล้อง และการกลับมาทำงานต่อ
- ตรวจภาพตามความกว้าง CSS 320, 375, 390, 768, 1024 และ 1440 พิกเซล

## เส้นทางทดสอบ

1. แอดมินสร้างผู้ใช้ กำหนดบทบาท และขอบเขตสถานี ตรวจการระงับบัญชีและสิทธิ์
2. สร้างสัญญาหลายภาค เพิ่มงวด เลือกสถานี และดูหน้าปก/รายงานสัญญา
3. สร้างสถานี SC และ IMPS โดยมี System, Asset, Lane, Scope, รายการไม่ครบ
   และรายการปิดใช้งาน ตรวจการแยก `SC-01–06`/`IMPS-01–06`, `.01` Equipment
   และ `.02` Systems & Software ตั้งแต่สร้างสถานีถึง Checklist และรายงาน
4. เจ้าหน้าที่เปิดรอบแบบผูกสัญญาและแบบด่วน ตรวจหมวดสถานี `1.1`, อุปกรณ์,
   ระบบ/ซอฟต์แวร์, สถานะ, หมายเหตุ และหลักฐาน
5. โหลดหน้าใหม่และตัดการเชื่อมต่อชั่วคราว แล้วตรวจว่างานที่ยังไม่ส่งหายหรือไม่
6. หัวหน้าตรวจความพร้อม ปิดรอบ เปิด Snapshot เก่า พิมพ์/ส่งออกรายงาน และ
   สร้างฉบับแก้ไขโดยไม่เขียนทับรอบต้นฉบับ
7. ทุกบทบาททดลองค้นหา ตัวกรอง ย้อนกลับ สถานะว่าง/ผิดพลาด และการเปิดสถานีที่
   อยู่นอกสิทธิ์ของตน

## ขนาดจอและสิ่งที่ต้องตรวจ

- ทุกเส้นทางใน `docs/design-system/route-map.md`: 390, 768 และ 1440 พิกเซล
- Checklist, สร้างสถานี, รายละเอียดสถานี, สร้างรอบ, หลักฐาน, Vehicle API และรายงาน:
  เพิ่ม 320, 375 และ 1024 พิกเซล
- ตรวจข้อความ/ปุ่มไม่ถูกตัด ไม่มีการเลื่อนแนวนอนโดยไม่ตั้งใจ ลำดับการเลื่อนถูกต้อง
  ปุ่มไม่ถูกบัง พื้นที่แตะอย่างน้อย 44 พิกเซล ป้ายกำกับช่องกรอกครบ และคีย์บอร์ดเข้าถึงงานหลักได้
- ตรวจข้อความบันทึกสำเร็จ/ไม่สำเร็จ สีและความคมชัด รวมถึงคำว่า Scope, Asset,
  System และ Snapshot ใช้ความหมายเดิมทุกหน้า

## เกณฑ์ผ่าน

- ผู้ทดสอบทำงานหลักโดยไม่รับคำใบ้ได้อย่างน้อย 80%
- ไม่มีปัญหาหยุดงาน สิทธิ์ผิด สถานีผิด ข้อมูลหาย หรือรายงานไม่ตรง Snapshot
- ไม่มีข้อความหรือการกระทำสำคัญถูกตัด และการกระทำหลักใช้ได้ทั้งแตะและคีย์บอร์ด
- ชื่อ/จำนวนหมวด SC และ IMPS ตรงกันตั้งแต่หน้าสร้างสถานีจนถึงประวัติและรายงาน
- หลังแก้ปัญหา ให้ผู้ทดสอบทำเส้นทางเดิมซ้ำบนอุปกรณ์และความกว้างจอเดิม

## การบันทึกผล

บันทึกบทบาท เส้นทางหน้า อุปกรณ์/ความกว้าง ขั้นตอนทำซ้ำ ผลที่ควรได้ ผลที่พบ
ระดับความรุนแรง ภาพ และสถานะ triage ตาม `docs/agents/triage-labels.md`
