วันที่: 29 กันยายน 2569  
สถานะ: ตรวจหน้าจอได้บางส่วน; ยังไม่ผ่าน UAT ทั้งระบบ เพราะไม่มีระบบทดสอบ บัญชีตามบทบาท และข้อมูลรอบตรวจ

- พบ UX ที่ควรแก้ 1 เรื่องใน Wizard มือถือ และข้อความผิดพลาดภาษาอังกฤษ 1 จุดที่ต้องให้เจ้าของระบบยืนยัน
- ยังไม่มีข้อมูลทดสอบ Contract/Inspection Round ใน Local Storage จึงไม่ถือภาพหน้าว่างของ Checklist ประวัติ และรายงานเป็นผลผ่าน

## ผลตรวจ UX/UI ที่ยืนยันได้

### 1. Wizard สร้างสถานีบนมือถือพาไปยัง Work Spec ยาก

ที่ 390 พิกเซล Work Spec เริ่มอยู่ต่ำจากด้านบนประมาณ 1,081 พิกเซล และที่ 320 พิกเซลอยู่ประมาณ 1,179 พิกเซล เพราะการ์ดหมวด 6 รายการเรียงอยู่ก่อนรายละเอียด เมื่อแตะ IMPS-01 ที่อยู่บนหน้าจอแล้ว หน้าไม่เลื่อนไปยังรายละเอียด ผู้ใช้ต้องเลื่อนเอง แต่ข้อความบนหน้าเขียนว่าเลือกหมวด “ทางซ้าย” แล้วดูเนื้อหา “ตรงกลาง” ซึ่งไม่ตรงกับการจัดวางมือถือ

รายละเอียดและภาพอยู่ใน [issue 04](issues/04-mobile-station-work-spec.md) สถานะ `ready-for-agent`

### 2. หน้าจัดการบัญชีแสดงข้อความยืนยันตัวตนเป็นภาษาอังกฤษ

หน้า `#/admin/users` แสดง `Authentication required` โดยไม่มีคำแนะนำให้เข้าสู่ระบบหรือขอสิทธิ์ ขณะเดียวกันยังเห็นช่องกรอกบัญชีอยู่ ภาพนี้มาจากระบบ Local ที่ไม่มีบัญชีทดสอบ จึงต้องยืนยันกับเจ้าของระบบว่าหน้านี้ควรแสดงคำแนะนำภาษาไทยหรือซ่อนฟอร์มเมื่อยังไม่ได้ยืนยันตัวตน

บันทึกใน [issue 05](issues/05-admin-auth-error-copy.md) สถานะ `needs-triage`; ยังไม่ได้ตรวจการสร้างบัญชีหรือสิทธิ์จริง

### 3. หน้ารายละเอียดสถานีที่ 320 พิกเซล

การ์ดสรุป Asset/System/Lane และรายการตรวจจัดเป็นสองคอลัมน์และยังอยู่ในกรอบจอ ไม่มีการล้นแนวนอนทั้งหน้า ภาพจากรอบจับใหม่อยู่ที่ `screenshots/station-detail-320.png` จึงถอนข้อสังเกตเรื่องการ์ดถูกตัดจากภาพรอบแรกซึ่งจำลองจอไม่ตรง

## ผลจากชุดทดสอบเดิมที่รันใหม่

รัน `node tools/run_all_tests.mjs`: พบ 71 ชุดทดสอบ และไม่ผ่าน 2 ชุด

1. `tools/test_item_library.mjs` คาดหวัง Asset 18 รายการ แต่ catalog ปัจจุบันให้ 17 รายการ; นิยาม 2 รายการเป็น `legacyOnly` ต้องให้เจ้าของข้อมูลยืนยันจำนวนที่ถูกต้อง ([issue 01](issues/01-item-library-count.md))
2. `tools/test_station_system_quantity.mjs` คาดหวัง `<option>` สำหรับเลือกกลุ่มมือถือ แต่ UI ปัจจุบันใช้ปุ่มใน nav; การลองจริงที่ 390 พิกเซลค้นหาและเลือกกลุ่มได้ แต่เจ้าของงานทดสอบยังต้องยืนยันว่าควรแก้ assertion ให้ตรวจพฤติกรรม ([issue 02](issues/02-mobile-station-group-selector.md))
3. การทดสอบที่ต้องใช้ฐานข้อมูลถูกข้าม เพราะไม่มี `CHECKLIST_POSTGRES_TEST_DATABASE_URL` และฐานทดสอบยืนยันตัวตนแยกต่างหาก
4. `tools/test_single_viewport_workspace.mjs` ตรวจ Source/CSS ไม่ได้เปิดเบราว์เซอร์วัด viewport จึงไม่ใช้แทนผลตรวจภาพรอบนี้

## สิ่งที่ยังไม่ได้รับรอง

เบราว์เซอร์รอบนี้ใช้ `VITE_STORAGE_MODE=local` บน origin แยกจากแท็บผู้ใช้ และมีข้อมูลเริ่มต้นเพียงสถานีตัวอย่าง 1 แห่ง ไม่มี Contract, Work Package, Inspection Round หรือบัญชีตาม role เรากรอกชื่อ/รหัสจำลองใน Wizard เพื่อไปดูขั้นถัดไป แต่ไม่ได้ยืนยันสร้างสถานี จึงไม่มีข้อมูลทดสอบถูกบันทึก

จึงยังไม่ได้ตรวจการกำหนดสิทธิ์ข้ามสถานี การสร้าง/ปิดรอบ การแนบรูปและการบันทึกหลังโหลดใหม่/ขาดเน็ต รายงานเทียบ Snapshot ประวัติฉบับแก้ไข หรือการทำงานของ Vehicle API กับข้อมูลทดสอบจริง ไม่ได้ทดสอบกับผู้ใช้จริง 6 คน มือถือ Android/iPhone คีย์บอร์ดทุกเส้นทาง ขนาดพื้นที่แตะ และเครื่องมืออ่านหน้าจอ

## ก่อนเริ่ม UAT

1. จัดระบบทดสอบที่ยืนยันฐานข้อมูลและพื้นที่ไฟล์แนบแยกจากระบบจริง
2. เตรียมบัญชี Field/Admin/Supervisor และข้อมูลจำลอง SC/IMPS, Contract, Work Package, หลักฐาน และ Vehicle API
3. นัดผู้ทดสอบอย่างน้อย 2 คนต่อบทบาท พร้อม Android/iPhone
4. ใช้ `test-cases.md` เก็บเวลาทำงาน จุดที่ต้องขอความช่วยเหลือ และหลักฐานแต่ละข้อ
5. แก้/ยืนยัน issues 01, 02, 04, 05 แล้วทดสอบซ้ำด้วยเส้นทางและอุปกรณ์เดิม

## สรุปการรับรอง

ผลชุดภาพยืนยันได้เฉพาะการจัดวางหน้าหลักที่ viewport ถูกต้องและการเลือกกลุ่ม SC/IMPS ในร่างที่ยังไม่บันทึก ยังรับรองการใช้งานจริงทั้งระบบไม่ได้ จนกว่าจะผ่านฐานทดสอบ บัญชีตาม role และผู้ทดสอบจริงตาม `issues/03-isolated-staging-and-testers.md`
